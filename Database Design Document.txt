1. Design Principles
Every table in PAGATEC follows these non-negotiable rules:
UUID Primary Keys: id String @id @default(uuid()) — prevents collision when devices create records offline.
Audit Columns: Every table has createdAt, updatedAt, createdBy, updatedBy.
Optimistic Locking: Every table has version Int @default(1) for conflict detection during sync.
Soft Deletes: Every table has deletedAt DateTime? — business data is never hard-deleted.
Tenant Isolation: Every table has businessId String — every query is scoped to one business.
Store/Warehouse Scoping: Where applicable, storeId and warehouseId enforce data boundaries.

14. Data Integrity Rules
14.1 Check Constraints
Product.salePrice >= 0
Product.costPrice >= 0
StockLevel.quantity >= 0 (unless BusinessSettings.allowNegativeStock = true)
CustomerCreditLimit.creditLimit >= 0
CustomerCreditLimit.currentBalance >= 0
POSTransaction.total >= 0
POSTransactionItem.quantity > 0
Shift.startingCash >= 0
14.2 Foreign Key Cascades
Soft delete only. No ON DELETE CASCADE on business-critical tables.
Business deletion: Soft delete cascades to all child records via application logic, not DB cascade.
User deletion: Set deletedAt on User; preserve all historical records (transactions, audit logs) with original createdBy.
14.3 Unique Constraints
Business.taxId (per active business)
Store.name (per business)
Product.sku (per business, active only)
Barcode.barcode (per business, active only)
Customer.customerNumber (per business)
Supplier.supplierNumber (per business)
User.email (per business)
Role.name (per business, if not system)
